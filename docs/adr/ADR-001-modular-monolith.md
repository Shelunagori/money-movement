ADR-001 — Context: We need to build a financial ledger where all entries belonging to a single operation must be committed atomically. Decision: Use a modular monolith with a separate worker process and a single PostgreSQL database. Consequences: We get single-database ACID transactions, which the core invariant relies on; module boundaries and discipline will need to be maintained manually; we should revisit this decision when a component requires a different deployment or availability profile, such as handling webhook traffic spikes.
