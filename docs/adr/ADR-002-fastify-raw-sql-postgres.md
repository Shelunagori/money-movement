ADR-002 — Context: Correctness depends heavily on PostgreSQL features such as transactions, locks, and constraints, so we do not want an abstraction layer that hides them. Decision: Use Fastify for boundary schema validation, async error handling, and built-in Pino logging, with raw SQL through pg. Consequences: SQL must be written and maintained manually, and there is no compile-time schema checking. Two rules are non-negotiable: always use parameterized queries with $1-style placeholders, and always execute a transaction using the same database client.
